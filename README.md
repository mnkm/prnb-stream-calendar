# PROJECT NEBULA Stream Calendar

YouTube チャンネルの **動画・ショート・ライブ配信** をカレンダーで表示する Web アプリ。
Cloudflare Workers(静的アセット + Hono API)+ D1 + Cron Triggers で動作します。

```
React SPA ──fetch──▶ Hono (/api/*) ──▶ D1
                                        ▲ upsert
        Cron (5 分ごと) ─── sync ───────┘──▶ YouTube Data API v3 / RSS
```

画面を開くたびに YouTube API を呼ぶのではなく、Cron で定期的に取得して D1 に保存しておき、画面は D1 から読みます。表示が速く、API の 1 日の使用量(クォータ)も抑えられます。

## 主な機能

| 機能 | 内容 |
|---|---|
| 表示の切り替え | **月 / 週 / 日 / リスト** をヘッダーで切り替え。初期表示はパソコンなどでは週、スマホ(幅 768px 未満)ではリスト(URL の `view` で指定したときはその表示) |
| 月表示 | 種別ごとの色のチップで表示。1 日 4 件以上は「+N 件」から日別一覧を開く。スマホでは色の点のみ |
| 週・日表示 | 0〜23 時を縦スクロールで表示し、予定を時刻の位置にブロックで置く。日付をまたぐ配信は始めた日の列に置き、24 時以降(25:00 など)まで表示を伸ばす。今日の列に現在時刻の線。日表示はサムネイル付き |
| リスト表示 | 月内の予定を日付ごとにサムネイル付きで表示。今月を開いたときは、予定が届いた時点で今日(今日に予定が無ければ次に予定がある日)の位置までスクロールする。ページを開いた直後はスクロールした状態から表示する |
| 詳細ダイアログ | 高画質サムネイル、日時・長さ、その場で再生(メンバー限定は YouTube へ誘導) |
| セットリスト | 歌枠の詳細ダイアログに、番号・曲名・アーティスト・時刻(hh:mm:ss)の一覧を表示。時刻を押すとダイアログ内で、右のアイコンを押すと YouTube(スマホはアプリ)で、その位置から再生 |
| 期間の移動 | 前後ボタン、「今日」、カレンダーの左右スワイプ(タッチ操作のみ) |
| 種別フィルター | ライブ / 動画 / ショートの表示切り替え(表示中の期間の件数付き) |
| キーワード検索 | タイトルを全期間から検索。全角・半角、大文字・小文字を区別しない。結果はリストで全件たどれる |
| テーマ | 最初は OS の設定に合わせたライト / ダークで表示し、ヘッダーのボタンでライトとダークを切り替え |
| チャンネル情報 | ヘッダー右端の YouTube ボタンでチャンネル一覧を開き、各チャンネルのバナー・@ハンドル・登録者数・動画数を表示。「再生リスト」と「チャンネル情報」(説明文、URL はリンク)のタブで切り替える |
| 再生リスト | チャンネルの再生リストをカードで表示(おすすめ系を先頭、残りは最近動画が追加された順)。押すと中身の一覧を開き(「再生リスト順」「新しい順」「古い順」で並べ替えでき、スクロールで続きを自動で表示)、動画の詳細へ進める。動画の詳細には「この動画が入っている再生リスト」を表示し、そこから再生リストへ移れる |
| 複数チャンネル | 2 チャンネル目を登録すると、チャンネルフィルターと色分けが自動で表示される。ヘッダー左端には並び順が先頭のチャンネル(01)のアイコンを表示する(押しても動作しない) |

表示の状態は URL に残るので、そのまま共有できます。

| パラメータ | 例 | 内容 |
|---|---|---|
| `view` | `month` / `week` / `day` / `list` | 表示モード |
| `date` | `2026-10-04` | 表示する日付(月・週表示ではその日を含む月・週) |
| `q` | `ASMR` | 検索語(指定すると検索結果を表示) |

以前の形式の `?month=2026-10` も開けます。

## API

| メソッド・パス | 内容 |
|---|---|
| `GET /api/channels` | 有効なチャンネルの一覧(名前・アイコン・色・説明・登録者数など) |
| `GET /api/events?from=&to=&channels=&types=` | 期間内の予定(最大 100 日分)。カレンダー表示に使う |
| `GET /api/search?q=&types=&channels=&cursor=` | キーワード検索。50 件ずつ新しい順に返す(後述) |
| `GET /api/setlist/:id` | 歌枠のセトリ(コメントの原文と書き手)。まだ見つかっていなければ 404 |
| `GET /api/channels/:id/playlists` | チャンネルの再生リスト(おすすめ系が先頭、残りは最後に動画が追加された順) |
| `GET /api/playlists/:id` | 再生リストの中身(このカレンダーに登録済みの動画だけ、再生リストの並び順) |
| `GET /api/videos/:id/playlists` | 動画が入っている再生リスト |
| `POST /api/admin/sync` | 手動同期。`Authorization: Bearer <ADMIN_TOKEN>` が必要 |

## データモデル(D1)

### `videos`

| 列 | 内容 |
|---|---|
| `id` | 動画 ID |
| `type` | `live` / `video` / `short` |
| `live_status` | `upcoming`(予定)/ `live`(配信中)/ `ended`(終了)。ライブとプレミア公開のみ |
| `event_at` | カレンダーに置く日時(UTC)。ライブ・プレミアは開始(予定)時刻、それ以外は公開日時 |
| `ended_at` | 配信の終了日時 |
| `duration_sec` | 動画の長さ |
| `members_only` | メンバー限定なら 1 |
| `search_title` | 検索用に正規化したタイトル(後述) |

ほかに `title`、`thumbnail_url`、`published_at`、`updated_at` など。

### `setlists`

歌枠のセトリ。コメントの原文(`text`)と書き手(`author`)、確認した日時(`checked_at`)、次に確認する日時(`next_check_at`)を持ちます。曲名・アーティスト・時刻への読み取りは表示のときに行うので、原文のまま保存しています。最後に点検した日時(`audited_at`)も持ちます。

### `setlist_audits`

セトリの点検で問題が見つかった歌枠。問題の内容(`problems`、JSON)、同じ問題を何度も知らせないための目印(`signature`)、見つかった日時(`found_at`)、Issue で知らせた日時(`notified_at`)を持ちます。問題が無くなれば行を消します。

### `playlists` / `playlist_items`

チャンネルが作った公開の再生リストと、その中身(どの動画が何番目に入っているか)。`items_synced_at` が NULL の再生リストは、中身の読み直しが必要なことを表します。

### `channels`

同期対象のチャンネル。`color`(複数チャンネル時の識別色)、`label`(表示・非表示ボタンに出す短いラベル)、`enabled`、プロフィール(`description` / `custom_url` / `banner_url` / `subscriber_count` / `video_count`、1 日 1 回更新)、過去分の取得の進み具合(`backfill_stage` / `backfill_page_token`)、一度だけ行う補正の進み具合(`premieres_*` / `members_*`)を持ちます。

## 同期の仕組み

Cron(5 分ごと)で、次の処理を行います。あわせて、チャンネルのプロフィール(`channels.list` の snippet / statistics / brandingSettings)を 1 日 1 回取り直します(1 ユニット)。

### サブリクエストの予算(Workers 無料プラン)

Workers 無料プランでは、1 回の実行で使えるサブリクエストが **外部への fetch と D1 の呼び出しを合わせて 50 回** までです。そのため同期処理は、1 回の実行で使う数を 45 回の予算(`src/worker/budget.ts` の `RequestBudget`)で数え、超えない範囲で進めます(D1 の `batch()` は 1 回として数える)。

- 取り込み済みチャンネルの差分同期は、**1 回の実行で 2 チャンネルまで**。最後に同期してから時間がたったものから順に回すので、6 チャンネルならそれぞれ約 15 分ごとに同期されます。
- 差分同期の書き込みは 1 回の `batch()` にまとめ、1 チャンネルあたり約 8 回(YouTube 5 回 + D1 3 回)で済むようにしています。
- 残りの予算で、過去分の取得と一度だけの補正を `sort_order` の順に進めます。

Workers Paid プランに切り替えた場合は、`src/worker/sync.ts` の `REQUEST_BUDGET` と `INCREMENTAL_CHANNELS_PER_RUN` を大きくすると、同期の間隔と過去分の取り込みを速くできます。

### 1. 過去分の取得(チャンネル登録直後)

1. 全アップロードのプレイリスト(`UU…`)を、予算の残りの範囲で 1 回あたり最大 8 ページ(400 件)ずつ取得し、数回の Cron に分けて進めます。
2. 最後まで取得したら、ショートのプレイリスト(`UUSH…`)でショートを判定します。

### 2. 差分同期(過去分の取得が終わったあと)

- RSS(クォータを消費しない)で新着を検知します。
- メンバー限定は RSS にも `UU…` にも含まれないため、メンバー限定のプレイリスト(`UUMO…`)の先頭も確認します。
- 新着と「予定・配信中」のライブだけを `videos.list` で取得し直します。予定時刻の変更や配信の開始・終了が反映されます。
- 待機所が削除・非公開になった配信は、`videos.list` に返ってこないので、カレンダーからも消します。

### 3. 一度だけの補正(差分同期の中で、終わるまで続ける)

- **プレミア公開**: 「動画」タブのプレイリスト(`UULF…`)を最後まで見て、ライブとして登録されたプレミア公開を動画に分類し直します。
- **メンバー限定**: `UUMO…` を最後まで取り込み、`UUMF…` でメンバー限定のプレミア公開を判定します。
- **検索用の列**: `search_title` が空の行を、1 回あたり 1,000 件ずつ埋めます。

### 4. セットリストの確認(残りの予算で)

タイトルに「歌枠」を含む、配信が終わった歌枠(メンバー限定を除く)のコメントを確認し、セトリを保存します。

- コメントを関連性順で 20 件取得し(1 ユニット)、上から見て最初に **タイムスタンプを 3 個以上含むコメント** をセトリとみなします。公式 API には「固定コメント」の印がありませんが、固定コメントは関連性順の先頭に来るので、ほとんどの場合は固定されたセトリが選ばれます。
- 見つからなければ、配信終了の **1・6・24 時間後、3・7 日後** に確認し直し、7 日を過ぎたらやめます。コメントが無効な配信は 1 回でやめます。
- 1 回の実行で確認するのは 10 本まで。過去の歌枠は新しいものから順に 1 回ずつ確認します。

### 5. セットリストの点検と通知

書き手が変わるなどして、読み取りの規則に合わない書き方のセトリが出てきたことに気づくための仕組みです。YouTube のクォータは使いません。

- **点検**: 取得したセトリ(と、7 日たっても見つからずにあきらめた歌枠)を、サイトの表示と同じ読み取り(`parseSetlist`)にかけて点検します(`src/shared/setlist-audit.ts`)。1 回の実行で 20 本まで。見るのは次のとおりです。
  - セトリが見つからない / 時刻があるのに曲が 1 曲も読み取れない / 曲が 2 曲以下
  - 曲以外(開始・挨拶・告知など)が曲として出ている / 曲名・アーティストに時刻・区切り記号・「※」が残っている
  - 時刻が前の曲より前・配信の長さを超えている / アーティストが空 / 曲名・アーティストが長すぎる
- **通知**: まだ知らせていない問題があれば、毎日 **9 時(JST)** を過ぎた最初の実行で、GitHub に Issue を 1 つ作ります(ラベル `setlist-check`、1 日 1 回、20 本まで)。Issue には動画のリンク、理由、該当する曲、元のコメントを載せます。
- Issue は持ち主のトークンで作るため、GitHub は持ち主に通知しません。そこで GitHub Actions(`.github/workflows/setlist-check-notify.yml`)が、作られた Issue に持ち主へのメンション付きのコメントを付け、メールなどで通知が届くようにしています。
- **同じ内容は二度と知らせません**。コメントと問題の内容(種類と該当する曲)が同じなら、取り直しても通知しません。読み取りの規則を直して結果が変わったときや、別のコメントに変わったときだけ、もう一度知らせます。問題がなければ Issue を閉じるだけで構いません。
- 読み取りの規則を直しても、点検済みのセトリは点検し直しません(取り直したときに点検します)。
- `GITHUB_TOKEN` が無ければ、点検だけ行い通知しません。

### 6. 再生リストの同期(残りの予算で)

- 各チャンネルの再生リストの一覧を **1 日 1 回** 取り直します(`playlists.list`、1 ユニット)。消えた再生リストは中身ごと削除します。
- **本数が変わった再生リスト(と新しい再生リスト)だけ**、中身を最初から読み直します(`playlistItems.list`、1 ページ 50 件で 1 ユニット)。1 回の実行で読むのは 8 ページまでで、続きは次回に持ち越します。
- おすすめ系(タイトルに「初見」「はじめて」「初めて」「まずはこれ」を含むもの)は、一覧の先頭に固定します(`src/shared/playlist.ts`)。メン限の再生リストも同じように表示します。
- 再生リストの中に、このカレンダーに無い動画(非公開・削除済みなど)があれば、本数には数えますが一覧には表示しません。

### 種別の判定

| 種別 | 判定方法 |
|---|---|
| ライブ | `liveStreamingDetails` があるもの |
| プレミア公開 | API ではライブと同じ形で返る。`UULF` / `UUMF` に含まれる、または公開前・公開中で動画の長さがある(ライブ配信は長さ 0)ものを **動画** として扱う。状態の追跡のため `live_status` は残し、API では動画として返す |
| ショート | `UUSH` に含まれるもの。プレイリストが使えないときは `/shorts/{id}` がリダイレクトされるかで判定 |
| 動画 | 上のどれにも当てはまらないもの |
| メンバー限定 | `UUMO` に含まれるもの(種別とは別に `members_only` を立てる) |

`UU` 以外のプレイリスト(`UUSH` / `UULF` / `UUMO` / `UUMF`)は YouTube の非公式な仕組みですが、広く使われています。

### クォータの目安(再生リスト)

最初に全チャンネルの再生リスト(6 チャンネルで約 90 件)を読むときに約 150〜200 ユニット。そのあとは一覧の取り直しが 1 日 6 ユニットと、本数が変わった再生リストの読み直しだけです。

### クォータの目安(セットリスト)

セトリの確認は 1 本 1 ユニットです。過去の歌枠(約 1,000 本)を一通り確認するまでは、1 日最大 2,880 ユニット(10 本 × 288 回)が加わり、そのあとは新しい歌枠 1 本につき最大 5 ユニットです。

### クォータの目安

差分同期 1 回で約 4〜5 ユニット(`UUSH` / `UULF` / `UUMO` の先頭と `videos.list`)です。各チャンネルを約 15 分ごとに同期するので、1 チャンネルあたり約 400〜500 ユニット/日、6 チャンネルで約 2,500〜3,000 ユニット/日です(上限は 10,000 ユニット/日)。過去分の取り込み中は、1 ページあたり 2 ユニットが加わります。

## 画面の実装メモ

### 時刻の表示

- 保存は UTC、表示はブラウザのタイムゾーン(日本なら JST)です。
- 月・週・リスト表示の時刻は **5 分単位で切り捨て** て表示します(例: 21:03 → 21:00)。配信は予定より数分遅れて始まることが多いためです。詳細ダイアログでは実際の時刻を表示します。

### 週・日表示(`TimeGridView`)

- ブロックの高さは、配信なら実際の長さ(予定は 1 時間、配信中は現在時刻まで)、動画は動画の長さです。短いものは読める最小の高さ(週 25 分 / 日 60 分ぶん)にそろえます。
- 時間が重なる予定は横に並べます。
- 予定は **配信を始めた日の列にだけ** 置きます。日付をまたぐ配信があれば、表示を 24 時以降(24:00, 25:00 … 最大 48:00)まで伸ばし、その時間帯は少し色を付けます。現在時刻の線は、前の日の列の 24 時以降にも引きます。
- 前の日に始まった配信は、次の日の列(日表示も)には出ません。
- 開いたときは、今日を含むなら現在時刻の少し前、それ以外は最初の予定の少し前までスクロールします。
- 週表示で日付の見出しを押すと、その日の日表示に切り替わります。

### 期間の移動とスワイプ

- 週・日表示も、その日を含む月グリッド(前後の週を含む)のデータで表示し、前後の月を先読みします。
- スワイプは Motion のドラッグで実装しています。タッチ操作のときだけ反応し、縦スクロールはブラウザに任せます(`touch-action: pan-y`)。80px 以上動かすか素早く払うと移動し、スワイプのあとに指を離した位置の予定は開きません。

### キーワード検索

- **全角・半角を区別しない仕組み**: SQLite には全角・半角をそろえる機能がないため、タイトルを NFKC で正規化して小文字にしたもの(例: `ＡＳＭＲ!` → `asmr!`、`ｼｬﾝﾌﾟｰ` → `シャンプー`)を `search_title` 列に保存しておきます。検索語も同じ規則でそろえてから `LIKE` で探します。正規化の規則は `src/shared/search.ts` で、画面と Worker が共有しています。
- `search_title` が空の行(列を追加する前に登録したもの)は、元のタイトルで検索します。同期で順に埋まります。
- スペース(全角も可)で区切ると、すべての語を含むものに絞り込みます。`%` や `_` は記号として扱います。
- **全件のたどり方**: 一度に全件を描くと重くなるため、50 件ずつ取得し、リストの下に近づくと続きを読み込みます。ページの区切りは `event_at` と ID のカーソルです。最初のページで種別ごとの一致件数を数え、全件の件数を表示します。種別・チャンネルの絞り込みはサーバー側で行います。
- 一致した語を強調表示します。600px 以上スクロールすると、右下に先頭へ戻るボタンが出ます。

### セットリストの表示

`src/shared/setlist.ts` の `parseSetlist` で、コメントの原文から曲だけを取り出します。書き手ごとに書き方が違うので、次のような形をまとめて扱います。

- 時刻: `0:06:19` / `00:09:46` / `03:14`。曲紹介・開始・終了の 3 つが並ぶ行は、曲の開始を使う
- 曲番号: `M01` / `🎶01.` / `01．` / `【01】` / なし(なければ 1 から振る)
- 曲名とアーティストの区切り: `／` / `/` / ` - `。コメントの中で一番多く使われているものを優先する(曲名に「/」を含む曲のため)
- 次の行に折り返した曲名・アーティストはつなげる。時刻だけの行の次の行に書かれた曲も読む
- 「3/30」「12／28」のように数字にはさまれた区切りは日付なので、曲名とアーティストの区切りにしない
- 曲以外の時刻(開始・OP・ED・告知・キリバンなど)と、補足(伴奏・作品名・発売日・リクエストした人・「少しアカペラ」などの演奏の補足・末尾の絵文字)は捨てる
- 「セトリ」の見出しがあり、その下(次の「タイムスタンプ」「雑談」などの見出しの手前まで)で 3 曲以上読めるときは、その部分だけを読む。セトリと目次(雑談も含む全体のタイムスタンプ)の両方に曲が書かれていても、セトリの方だけが出る
- 見出しが無く、同じ曲が 2 回書かれている場合や、日本語と英語で 2 回書かれている場合は、最初の 1 回だけにする(両方に番号が付いた歌い直しは残す)
- 「スタートライン!,アイカツスターズ / Start Line!, Aikatsu Stars!」のように、日本語と英語を「/」で分け、曲名とアーティストを「,」で区切ったセトリは、日本語の方を読む
- アーティストのあとに「,」で続く補足(「, ピアノ伴奏」「, New」)は外し、「鏡音リン, 鏡音レン」のような連名は残す
- 区切りが 1 つも無いときは、「セトリ」の見出しの下の行や「(歌)」の印の行を、曲名だけの曲として読む
- 番号が無い・重なったり戻ったりしているときは 1 から振り直す
- アーティストが書かれていないオリジナル曲は、`KNOWN_ARTISTS` の対応表で補う(例: Swing Days! → 碓氷ゆら。大文字・小文字は区別しない)

曲が 1 曲も読み取れないとき(歌枠リレーの開会式など)は、セトリ欄を表示しません。セトリはファンの方が書いたものなので、一覧の下に書き手を表示しています。

### テーマ

ボタンで切り替えるまでは OS の設定(`prefers-color-scheme`)に合わせ、OS の設定が変わればそれに付いていきます。ボタンで選んだテーマは `<html data-theme>` と `localStorage` に保存します。`index.html` のインラインスクリプトで描画前に当てるので、読み込み時に一瞬別の色になることはありません。色は `src/client/index.css` の CSS 変数で定義しています。

## セットアップ

### 1. YouTube Data API キー

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. 「YouTube Data API v3」を有効化
3. 認証情報 → API キーを作成し、**API の制限** で YouTube Data API v3 のみに制限
   (サーバー側から呼ぶため、HTTP リファラー制限は設定しない)

### 2. ローカル開発

```bash
npm install
cp .dev.vars.example .dev.vars   # YOUTUBE_API_KEY と ADMIN_TOKEN を記入
npm run db:migrate:local
npm run dev                      # http://localhost:5173
```

初回データの取り込み(過去分が多い場合は数回実行):

```bash
curl -X POST -H "Authorization: Bearer <ADMIN_TOKEN>" http://localhost:5173/api/admin/sync
```

Cron の処理は `http://localhost:5173/cdn-cgi/handler/scheduled` を開くと手動で動かせます。

### 3. Cloudflare へのデプロイ

```bash
npx wrangler login
npx wrangler d1 create prnb-youtube-calendar   # 出力された database_id を wrangler.jsonc に記入
npm run db:migrate:remote
npx wrangler secret put YOUTUBE_API_KEY
npx wrangler secret put ADMIN_TOKEN
npx wrangler secret put GITHUB_TOKEN      # セトリの点検の Issue 用(下記)
npm run deploy
```

`GITHUB_TOKEN` は、GitHub の Settings → Developer settings → Personal access tokens → **Fine-grained tokens** で作ります。Repository access は このリポジトリだけ、Permissions は **Issues: Read and write** だけにします。トークンには有効期限があり、切れると Issue が作られなくなる(Workers のログに `setlist audit failed` が出る)ので、期限前に作り直して `secret put` し直してください。Issue を作るリポジトリは `wrangler.jsonc` の `vars.GITHUB_REPO` で指定します。

### 4. GitHub 連携(自動デプロイ)

1. このリポジトリを GitHub に push
2. Cloudflare ダッシュボード → Workers & Pages → `prnb-youtube-calendar` → Settings → Builds → **Connect** で GitHub リポジトリを接続
3. Build command: `npm run build` / Deploy command: `npx wrangler deploy`

以降は `main` への push で本番デプロイされます。`main` 以外のブランチの push ではプレビュー版がアップロードされ、本番には影響しません。

## 運用

### ブランチと本番反映の流れ

1. `develop` ブランチで開発して push する
2. スキーマを変更した場合は、**先に** 本番の D1 にマイグレーションを反映する(D1 のマイグレーションは自動では適用されません)

   ```bash
   npm run db:migrate:remote
   ```

3. `develop` を `main` に取り込んで push すると、本番にデプロイされる

マイグレーションは列の追加だけにしておくと、新しいコードのデプロイ前に反映しても、動いている本番に影響しません。

### Cron(同期の間隔)を変えるとき

GitHub 連携の自動デプロイでは、コードは更新されても **Cron の設定は本番に反映されません**。`wrangler.jsonc` の `triggers.crons` を変えて `main` に取り込んだあと、プロジェクトのフォルダで次を実行してください。

```bash
npm run build                 # Cron の設定を含むデプロイ用の設定ファイルを作り直す
npx wrangler triggers deploy  # Cron の設定だけを本番に反映する
```

- 実行すると `schedule: */5 * * * *` のように、反映された設定が表示されます。ダッシュボードの Workers & Pages → `prnb-youtube-calendar` → Settings → Trigger events でも確認できます。
- 設定を変えてから実際の実行間隔が切り替わるまで、20 分ほどかかることがあります。切り替わるまでは前の間隔のまま実行されます(ダッシュボードの「Cron イベント」の `Cron` 列で、どちらの設定で実行されたかがわかります)。

| マイグレーション | 内容 |
|---|---|
| `0001_init.sql` | `channels` / `videos` テーブル |
| `0002_seed_channel.sql` | 初期チャンネル(碓氷ゆら / Yura Usui) |
| `0003_premieres_scan.sql` | プレミア公開の補正の進み具合 |
| `0004_members_only.sql` | メンバー限定の列と、取り込みの進み具合 |
| `0005_search_title.sql` | 検索用に正規化したタイトルの列 |
| `0006_channel_profile.sql` | チャンネルのプロフィール(説明・@ハンドル・バナー・登録者数・動画数) |
| `0007_setlists.sql` | 歌枠のセットリスト |
| `0008_playlists.sql` | 再生リストとその中身 |
| `0009_setlist_audits.sql` | セトリの点検の結果(既存のセトリは点検済みにする) |
| `0010_channel_label.sql` | チャンネルの表示・非表示ボタンに出す短いラベル |
| `0011_channel_label_ja.sql` | ラベルを絵文字から日本語の名前に変える(01 は「公式」のまま) |

### チャンネルの追加

ID を 1 行追加するだけで、次の Cron から過去分の取り込みが始まります(タイトルとアイコンは自動取得)。

```bash
npx wrangler d1 execute prnb-youtube-calendar --remote \
  --command "INSERT INTO channels (id, color, sort_order) VALUES ('UCxxxxxxxxxxxxxxxxxxxxxx', '#f472b6', 1)"
```

2 チャンネル以上になると、画面にチャンネルフィルターと色分けが自動で表示されます。`sort_order` が画面での並び順です。 `color` には CSS の色をそのまま書けます。`var(--ink)` を指定すると、ライトテーマでは黒、ダークテーマでは白になります。`label` を入れると、チャンネルの表示・非表示を切り替えるボタンにチャンネル名の代わりに表示します(例: `公式`、`桃瀬にな`)。

チャンネルを増やすと、各チャンネルの同期の間隔が延びます(無料プランでは「チャンネル数 ÷ 2 × 5 分」ごと)。また、YouTube API の 1 日の上限(10,000 ユニット)にも近づくので、10 チャンネルを超える場合は Workers Paid プランへの切り替えを検討してください。

## 既知の制限

- **メンバー限定から一般公開に変わった動画**: 「メン限」ラベルが付いたままになります。
- **予定日時を過ぎた配信予定**: 待機所が残っている限り、YouTube が「配信予定」として返すため、カレンダーにも予定として表示されます。
- **非公式のプレイリスト**: `UUSH` / `UULF` / `UUMO` / `UUMF` の仕様が変わると、ショート・プレミア公開・メンバー限定の判定に影響します。
- **検索の強調表示**: 半角カタカナの濁点(`ｶﾞ` など)を含む語は、検索では一致しても、強調表示されないことがあります。
